💡 과제 2 핵심 요약: 우리는 왜 이 작업을 하나요?
현재 국가 OpenAPI는 '공무원 중심의 행정 문서' 형태로 제공되고 있습니다. 그러나 대규모 언어 모델(LLM)에 이를 그대로 주입하면, AI는 명확한 분모나 기준을 찾지 못해 지어내는 현상(환각)을 일으키게 됩니다.

따라서 우리가 KOSIS API에 흩어진 파편화된 데이터들을 모아서, AI가 헷갈리지 않도록 [설명자료(6대 필드) + 온톨로지] 규격의 JSON 정답지로 예쁘게 조립해 주는 것입니다.

이 과정을 통해 "이런 작업은 수작업으로는 한계가 있으니, AI가 추출하고 사람이 검수하는 자동화 R&D 사업이 필요하다"는 멋진 정책적 제안을 이끌어내 보는 것이 이 프로젝트의 최종 목표라고 할 수 있습니다.

Deep Dive: Core Concepts
우리가 만들 '설명자료'와 '온톨로지'란 무엇일까요?

'메타데이터'라는 큰 우산 안에는 설명자료와 온톨로지가 모두 포함됩니다. 기존 KOSIS API의 어려운 글들을 AI가 오독하지 않게 하려면, 우리는 이 두 가지를 직접 조립하여 하나의 완벽한 정답지로 만들어 주어야 합니다.

요소 1. 설명자료 (Descriptive)
지표의 "신분증 (요약 노트)"
이 통계 지표가 무엇을 의미하는지 AI가 헷갈리지 않게 딱 6가지 핵심 정보(정의, 분모, 단위, 기간, 지역, 출처)만 뽑아 채우는 과정입니다. 긴 줄글 대신 이 요약 노트 안에서만 대답하도록 기준을 세워줍니다.
요소 2. 온톨로지 (Semantic)
지표들의 "개념 지도 (가계도)"
"그럼 생산가능인구는 뭐야?" 같은 꼬리 질문에 AI가 길을 잃지 않도록 방어하는 역할을 합니다. 통계 용어 간의 상하 관계나 포함/제외 기준을 엮어주는 친절한 내비게이션 네트워크라고 보시면 됩니다.

통계 환각을 막아줄 6대 필수 필드 (설명자료)

1. 정의 (Definition)
이 통계 지표가 측정하려는 바를 명확하게 적어줍니다.
예시: 생산가능인구 100명당 고령인구의 비율
2. 분모 (Denominator) 가장 중요
계산 시 기준이 되는 전체 집단이 정확히 무엇인지 명시합니다. 이 부분이 빠지면 AI가 맘대로 상상하게 됩니다.
예시: 15~64세 생산가능인구
3. 단위 (Unit)
해당 수치를 세는 기준(%, 명, 건 등)을 정의합니다.
예시: 명 (100명당)
4. 기간 (Period)
이 통계가 측정된 시점이나 조사 주기를 명시합니다.
예시: 매월
5. 지역 (Region)
포괄하고 있는 지리적, 행정적 범위를 명시합니다.
예시: 전국 및 17개 시도
6. 출처 (Source)
신뢰할 수 있는 공식적인 발행 기관을 명시합니다.
예시: 통계청, 인구주택총조사
API Data Mapping Recipe
"이 두 가지를 만들기 위해 API를 어떻게 조립할까요?"

단일 API 하나만으로는 우리가 원하는 완벽한 룰셋을 만들 수 없습니다. 그래서 우리는 통계목록(1.1.1), 통계자료(1.1.2), 통계설명(1.1.4), 메타자료(1.1.5), 주요지표(1.1.7) API 요소들을 조금씩 꺼내어, 하나의 기계 해독형 JSON으로 재조립(Mapping)해 보려고 합니다.

Q1. 이 지표의 진짜 '분모(기준)'는 무엇일까요?
API 결과 중 "조사대상"이나 "조사목적"을 읽어보고 분모가 될 만한 문장을 찾아보세요. (예: 아, 전체 인구가 아니라 '경제활동인구'구나!)

Q2. AI가 헷갈려서 지어낼 만한 단어가 있을까요? (온톨로지 후보 찾기)
API 설명 문장을 읽다 보면 "경제활동인구", "가임여성" 같은 단어가 나옵니다. 'AI가 이 단어의 정확한 범위를 알까?' 생각해 보고, 헷갈릴 것 같은 단어를 1~2개 픽(Pick) 해오시면 좋겠습니다.

Q3. 용어사전에서 그 단어의 뜻 찾아보기
